# 0001. Kotlin Multiplatform + Compose Multiplatform на всех платформах

- Статус: Принято
- Дата: 2026-09-24

## Контекст

Нужно выпустить приложение для Android, iOS, macOS и Windows силами одного разработчика.
Разработчик хочет писать на Kotlin. Приложению нужен глубокий доступ к платформе: PhotoKit, MediaStore,
фоновые задачи, mDNS, Keychain/Keystore, локальный HTTPS-сервер на ПК.

## Решение

- **Kotlin Multiplatform** для всей логики: медиатека, дубли, коннекторы облаков, протокол передачи, БД.
- **Compose Multiplatform** для интерфейса на всех платформах, включая desktop (JVM) и iOS
  (стабилен на iOS с версии 1.8.0, май 2025).
- Платформенный код — через `expect`/`actual` и интерфейсы с реализациями по платформам.
- На iOS — тонкая оболочка на Swift; Swift-код только там, где без него нельзя.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| KMP-логика + нативный UI (SwiftUI, Jetpack Compose, отдельный desktop UI) | UI пришлось бы писать 3 раза — нереально для одного человека |
| Flutter | другой язык (Dart), слабее доступ к платформенным API из общего кода, разработчик выбрал Kotlin |
| React Native / Electron | JS-стек, тяжёлый desktop, хуже производительность сетки на 50k превью |
| Нативно на каждой платформе | 4 кодовые базы |

## Последствия

- ➕ 80–85% общего кода, единая дизайн-система.
- ➕ Desktop на JVM даёт Linux почти бесплатно и зрелые библиотеки (Ktor Server, JmDNS, BouncyCastle).
- ➖ Compose на iOS рисует интерфейс сам: не получает автоматически «Liquid Glass» iOS 26,
  нужно отдельно следить за жестами, клавиатурой, VoiceOver. Закрываем дизайн-системой и чек-листом,
  а навигацию на iOS делаем на SwiftUI — [ADR 0009](0009-liquid-glass-native-navigation.md).
- ➖ Desktop-сборка тяжелее нативной (встроенная JVM, ~100 МБ).
- ➖ Для iOS нужен Mac: Kotlin/Native собирает Apple-таргеты только на macOS.
- Риск: библиотека «Фото» на macOS недоступна из JVM напрямую → нативный помощник на Swift в v1.x.
