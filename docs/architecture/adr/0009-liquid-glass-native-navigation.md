# 0009. Liquid Glass на iOS и macOS: нативная навигация, экраны на Compose

- Статус: Принято, детали уточняются спайками S-08 и S-09
- Дата: 2026-09-25

## Контекст

- По [ADR 0001](0001-kotlin-multiplatform-compose.md) интерфейс на всех платформах пишется на Compose
  Multiplatform. Compose рисует всё сам, в одном слое Metal, и системных материалов iOS 26 и macOS Tahoe
  не получает.
- Liquid Glass — системный материал: `glassEffect` в SwiftUI, `UIGlassEffect` в UIKit, `NSGlassEffectView`
  в AppKit. Он преломляет контент под собой, подстраивает тень и цвет под фон, меняет форму при переходах
  и сам учитывает «Уменьшить прозрачность» и «Увеличить контраст».
- Имитация в Compose (размытие и полупрозрачная заливка) даёт матовое стекло, но без преломления, морфинга
  и системных настроек доступности. На iPhone разница заметна сразу.
- Макеты iPhone, iPad и macOS ([холст](../../design/README.md#макеты), ряды «iPhone и iPad» и «macOS») построены
  по правилам Liquid Glass: стекло только на слое навигации, контент — обычные поверхности.
- Mac и iPhone у владельца есть: спайки можно делать сразу, без Apple Developer Program.

## Решение

**Правило владельца:** интерфейс пишем на Compose. То, что Compose на iOS и Mac не умеет или делает заметно
хуже системы, делаем на SwiftUI (при необходимости — UIKit или AppKit).

| Платформа | Нативно (SwiftUI) | Compose |
|---|---|---|
| iPhone, iPad | навигация: панель вкладок и поиск, заголовки и кнопки на стекле, листы, панель действий при выделении; сканер QR (VisionKit), системные «Поделиться» и выбор фото | содержимое экранов: лента, списки, карточки, уборка, настройки |
| macOS | стекло окна (сайдбар, панель инструментов), панель в строке меню, окно настроек | основное окно: лента, хранилища, уборка, архив, устройства |

### iPhone и iPad

- **Слой навигации — SwiftUI.** Панель вкладок и кнопка поиска — `TabView` (на iPad — сайдбар через
  `.sidebarAdaptable`). Заголовки, кнопки на стекле и «назад» — `NavigationStack` с `.toolbar`.
  Листы — `.sheet` с уровнями высоты. Панель действий при выделении — нижний `.toolbar`. Стекло рисует система.
- **Экраны — Compose.** Содержимое каждого экрана — `ComposeUIViewController` из общего кода,
  встроенный в SwiftUI через `UIViewControllerRepresentable`. Лента, списки, карточки и уборка — общие
  компоненты `:shared:designsystem`.
- **Состояние навигации — в общем Kotlin-коде** (ViewModel разделов). SwiftUI показывает его и сообщает
  о нажатиях. Swift-кода — оболочка на несколько сотен строк, как и задумано в ADR 0001.
- Цветное стекло — только у одного главного действия на экране (`.buttonStyle(.glassProminent)`).
- На iOS 16–25 те же компоненты SwiftUI выглядят по-старому, без стекла. Отдельный код не нужен.

### macOS

- Основное окно — **Compose Desktop (JVM)**. Стабильного нативного macOS-таргета для UI у Compose
  Multiplatform нет, а всё окно на SwiftUI означало бы третью копию UI.
- Нативные части живут в том же процессе: AppKit там уже работает. Небольшая Swift-библиотека
  (`apps/macos-native`, Swift Package с динамической библиотекой) создаёт SwiftUI-вью (`NSHostingView`)
  и системное стекло (`NSGlassEffectView`). Kotlin вызывает её через Foreign Function & Memory API
  (входит в JDK 25), без JNA.
- **Стекло окна:** `NSGlassEffectView` под прозрачными областями окна Compose — сайдбар и панель инструментов.
  Если спайк S-09 покажет, что это нестабильно, — непрозрачная заливка, как на макетах.
- **Строка меню:** `NSStatusItem` с всплывающей панелью на SwiftUI (макет `M-MenuBar`).
- **Настройки:** отдельное окно на SwiftUI с `Form` (макет `M-Settings`).
- Swift-библиотека собирается только на macOS (задача Gradle вызывает `swift build`) и кладётся в ресурсы
  приложения в `.dmg`. На Windows и Linux её нет.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Весь интерфейс iOS на Compose, стекло — имитация | нет преломления, морфинга, адаптации к фону и настроек доступности: выглядит «почти как iOS» |
| Весь интерфейс iOS на SwiftUI, KMP только для логики | второй UI целиком, около 30 экранов; одному разработчику не по силам, противоречит ADR 0001 |
| Стеклянные вью UIKit внутри Compose (`UIKitView` с `UIGlassEffect`) | системной навигации всё равно нет: панели, группировку и морфинг пришлось бы собирать вручную. Оставляем запасным путём для кнопок поверх фото |
| macOS целиком на SwiftUI | третья копия UI |
| Нативные части Mac через JNA | FFM уже есть в JDK 25: без лишней зависимости и быстрее |
| Ждать нативных материалов в Compose Multiplatform | сроков нет. Пересмотрим решение, если они появятся |

## Последствия

- ➕ Настоящий Liquid Glass там, где он заметнее всего: панель вкладок, панели инструментов, листы.
- ➕ Системные жесты, «назад», VoiceOver, «Уменьшить прозрачность» и «Увеличить контраст» — от системы.
- ➕ Экраны остаются общими: основная часть UI-кода — Compose.
- ➕ Одно правило для iPhone и Mac: где Compose не дотягивает до системы — SwiftUI.
- ➖ Два мира навигации: нужен тонкий мост между SwiftUI и общим состоянием, навигацию на iOS тестируем отдельно.
- ➖ Прокрутка Compose — не `UIScrollView`. Поэтому системный эффект края прокрутки и сворачивание панели
  вкладок при прокрутке не срабатывают. В Compose рисуем мягкое затухание у краёв, как на макетах;
  сворачивание панели не используем.
- ➖ В нативных панелях — системный шрифт SF Pro, в контенте — Onest. Принимаем.
- ➖ На Mac появляется Swift-библиотека: собирается только на macOS, в CI — на macOS-раннере.
- ➖ Стекло окна на Mac — самое рискованное место; запасной вариант — непрозрачная заливка.
- Риск: Compose и UIKit в одном окне — возможны проблемы с фокусом и клавиатурой. Проверяем в S-08.
