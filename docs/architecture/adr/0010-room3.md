# 0010. Room 3 для локальной базы

- Статус: Принято, заменяет [0004](0004-sqldelight.md)
- Дата: 2026-09-25

## Контекст

[ADR 0004](0004-sqldelight.md) выбрал SQLDelight, потому что Room 3 был в альфе, и велел пересмотреть решение,
когда Room 3 станет стабильным. Это случилось: Room 3.0.0 вышел 1 июля 2026, текущая стабильная версия — 3.0.3.

Требования к базе прежние: Android, iOS и JVM desktop; десятки тысяч записей; группировки по хэшам и поиск
похожих через индексы; пагинация; реактивные запросы (`Flow`); миграции без потери данных.

Кода ещё нет, поэтому сменить библиотеку сейчас ничего не стоит.

## Решение

**Room 3** (`androidx.room3`) в модуле `:shared:database`:

- сущности, DAO и `@Database` — в `commonMain`; конструктор базы генерирует Room (`@ConstructedBy`);
- кодогенерация — KSP для каждого таргета: `kspAndroid`, `kspJvm` (desktop), `kspIosArm64`, `kspIosSimulatorArm64`;
- драйвер — `BundledSQLiteDriver` (`androidx.sqlite:sqlite-bundled`): одна и та же версия SQLite
  на всех платформах;
- запросы — `suspend`-функции и `Flow`, диспетчер задаётся через `setQueryCoroutineContext`;
- пагинация ленты — `room3-paging` и Paging 3;
- схема каждой версии экспортируется в `shared/database/schemas/` (плагин `androidx.room3`) и хранится в репозитории;
  миграции проверяются тестами на JVM.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| SQLDelight 2 | тоже подходит. Room 3 выбран, потому что теперь покрывает все нужные платформы, а его API знаком большинству Android-разработчиков — новым участникам проще. SQL в `@Query` проверяется при компиляции так же |
| Room 2.8 (KMP) | переведён в режим поддержки, новые возможности — только в Room 3 |
| Realm Kotlin | не реляционная модель, развитие проекта замедлилось |

## Последствия

- ➕ API, знакомый большинству Android-разработчиков, поддержка Google, официальные артефакты для Paging и тестов.
- ➕ Одна версия SQLite везде благодаря встроенному драйверу.
- ➕ Сложные запросы (дубли, группировки, полосы pHash) пишутся на SQL в `@Query` и `@RawQuery`.
- ➖ KSP и отдельный запуск кодогенерации на каждый таргет замедляют сборку iOS.
- ➖ Встроенный SQLite добавляет несколько мегабайт к размеру приложения.
- Правило из [модели данных](../data-model.md#миграции) не меняется: после релиза базу не пересоздаём,
  только миграции.
