# 0003. Связка устройств по QR вместо аккаунтов

- Статус: Принято
- Дата: 2026-09-24

## Контекст

Нужно, чтобы телефон «видел» компьютеры пользователя (их может быть несколько) и мог безопасно
отправлять им фото. Классический вариант — общий аккаунт с почтой и паролем — требует сервера и хранения
персональных данных (см. [0002](0002-local-first-no-backend.md)).

## Решение

- Каждое устройство создаёт свой ключ ECDSA P-256 (приватная часть не покидает устройство).
- ПК показывает QR-код с отпечатком своего TLS-сертификата, адресами и одноразовым секретом.
- Телефон сканирует QR, проверяет сертификат ПК по отпечатку и доказывает знание секрета (HMAC).
- ПК просит пользователя подтвердить подключение.
- Дальше устройства узнают друг друга по публичным ключам.

UX — как вход в Telegram Desktop или WhatsApp Web: для пользователя это и есть «вход в аккаунт».

## Альтернативы

| Вариант | Почему нет |
|---|---|
| Email + пароль | нужен сервер, восстановление, хранение персональных данных |
| Sign in with Apple / Google / Яндекс ID | тоже нужен сервер для связки устройств; разный набор провайдеров на разных платформах |
| Ввод кода из 6 цифр | хуже защищает от подмены ПК; оставим как запасной вариант, если камера недоступна |

## Последствия

- ➕ Никаких паролей и почты, работает офлайн, нет сервера.
- ➕ Сильная криптографическая привязка устройств друг к другу.
- ➖ Нет восстановления «через почту»: при потере всех устройств связку создают заново (фото не теряются).
- ➖ Каждый ПК связывается отдельно. Синхронизация списка устройств — позже.
